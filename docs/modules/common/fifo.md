# fifo

## Назначение

Синхронная очередь фиксированной глубины с комбинационным выходом головного элемента. В передатчике хранит слова внутри `axis_input_fifo` до их захвата контроллером.

## Порты

### Параметры

`WIDTH=32` задаёт ширину элемента. `DEPTH=16` задаёт число элементов. Глубина должна быть степенью двойки не меньше 2, чтобы адреса указателей циклически проходили весь массив.

| Порт | Направление | Ширина или тип | Назначение |
| --- | --- | --- | --- |
| `clk` | Вход | 1 | Операции по положительному фронту. |
| `rst_n` | Вход | 1 | Асинхронный активный низкий reset указателей. |
| `w_en` | Вход | 1 | Запрос записи, принимается при !full. |
| `w_data` | Вход | WIDTH | Записываемое слово. |
| `r_en` | Вход | 1 | Запрос удаления головного слова, принимается при !empty. |
| `r_data` | Выход | WIDTH | Головное слово, значимо при !empty. |
| `full` | Выход | 1 | Все DEPTH элементов заняты. |
| `empty` | Выход | 1 | Слова отсутствуют. |

## Логика работы

### Указатели и флаги

Адреса записи и чтения состоят из младших `$clog2(DEPTH)` битов указателей. Старший бит каждого указателя отмечает оборот по массиву. `empty=1`, если указатели совпадают полностью. `full=1`, если совпадают адреса, а биты оборота различаются.

### Запись и удаление головного слова

Разрешения `push = w_en && !full` и `pop = r_en && !empty` вычисляются по состоянию перед фронтом. При push записывается `mem[waddr]` и увеличивается `wptr`. При pop увеличивается `rptr`. Когда оба разрешены, число элементов сохраняется.

На полном FIFO одновременные w_en/r_en выполняют только pop. На пустом FIFO выполняется только push, новое слово доступно после фронта. Передача входного слова непосредственно потребителю в обход памяти отсутствует.

`r_data` комбинационно читает `mem[raddr]`. Потребитель захватывает старое головное слово на фронте, на котором выполняется `pop`. Если pop отсутствует и FIFO непусто, головное слово сохраняется. Выход при empty может содержать старые или неопределённые данные.

### Сброс

`rst_n=0` асинхронно обнуляет оба указателя. Поэтому `empty=1`, `full=0`, а данные на `r_data` до новой записи не имеют значения. Содержимое массива памяти при сбросе сохраняется.
