# tx_regs и tx_regs_pkg

## Назначение

`tx_regs` хранит конфигурацию, аппаратные поля и `INT_STATUS_REG`. Пакет `tx_regs_pkg` объявляет структуры tx_regs__in_t/tx_regs__out_t и константы TX_REGS_DATA_WIDTH=8, TX_REGS_MIN_ADDR_WIDTH=6, TX_REGS_SIZE=0x2C.

CPU-интерфейс подключён внутри [spi_tx_regs_wrapper](spi_tx_regs_wrapper.md). Аппаратные структуры соединяются с [tdl_tx_reg_bridge](tdl_tx_reg_bridge.md).

## Порты

| Порт | Направление | Ширина или тип | Назначение |
| --- | --- | --- | --- |
| `clk` | Вход | 1 | Системный такт. |
| `rst` | Вход | 1 | Синхронный активный высокий reset сгенерированных регистров. |
| `s_cpuif_req` | Вход | 1 | Запрос доступа. |
| `s_cpuif_req_is_wr` | Вход | 1 | 1 для записи, 0 для чтения. |
| `s_cpuif_addr` | Вход | 6 | Байтовый адрес. |
| `s_cpuif_wr_data` | Вход | 8 | Данные записи. |
| `s_cpuif_wr_biten` | Вход | 8 | Побитовая маска записи. |
| `s_cpuif_req_stall_wr`, `s_cpuif_req_stall_rd` | Выход | По 1 | Запрет принятия соответствующего запроса. |
| `s_cpuif_rd_ack`, `s_cpuif_wr_ack` | Выход | По 1 | Подтверждение завершённого доступа. |
| `s_cpuif_rd_err`, `s_cpuif_wr_err` | Выход | По 1 | Ошибка соответствующего доступа. |

| `hwif_in` | Вход | tx_regs_pkg::tx_regs__in_t | Аппаратные значения для регистров. |
| `hwif_out` | Выход | tx_regs_pkg::tx_regs__out_t | Поля конфигурации и текущие IRQ-статусы. |

## Логика работы

### Байтовый доступ

В passthrough-интерфейсе `stall_rd/stall_wr` равны 0, а `ack` соответствующего направления действителен в такте принятия `req`. Флаг генерации `--err-if-bad-addr` включает ошибку для адресов вне карты. Wrapper выбирает ошибку по направлению доступа и соответствующему `ack`.

### Карта регистров

| Диапазон | Группа | Основной владелец данных |
| --- | --- | --- |
| 0x00–0x06 | CTRL, MODE, период, BF, SLRU и команды | CSR, безопасные активные настройки формирует bridge. |
| 0x07 | STATUS | FIFO, controller и bridge через hwif_in. |
| 0x08–0x09 | Разрешения и sticky-статусы IRQ | tx_regs. |
| 0x0A–0x0B | CRC и порог hit-rate | CSR, CRC исключён базовым планом. |
| 0x0C–0x1F | Пять 32-битных счётчиков | stats через bridge. |
| 0x20–0x21 | Два байта делителя SDR | CSR. |
| 0x22–0x2B | I²C | Хранение конфигурации. Аппаратные статусы подаются мостом как 0. |

Входы значений используют `next`, входы установки IRQ — `hwset`, выходы полей — `value`.

### Установка и очистка прерываний

RDL задаёт `hwset`, `precedence = hw` и `onwrite = woclr`. `tx_regs` хранит sticky-статус, а при совпадении установки и W1C новое событие имеет приоритет. Для каждого бита действует

```text
status_next = (status_current & ~software_w1c) | hardware_event
```

Bridge подаёт события на `hwif_in.INT_STATUS_REG.<field>.hwset`. Wrapper применяет `INT_ENABLE_REG` при формировании `spi_irq`.

### Согласованное чтение счётчиков

Общий тип пяти счётчиков задаёт `regwidth=32`, `accesswidth=8` и `buffer_reads`. Чтение младшего байта возвращает его текущее значение и фиксирует все 32 бита на фронте приёма CPUIF. Чтения старших трёх байтов используют сохранённое значение. Повторное чтение младшего байта обновляет снимок. Software читает четыре байта по возрастанию адреса.

### Подключение аппаратных функций

Мост подаёт `0` в `CONFIG_PENDING`, `FLUSH_BUSY`, `RESET_BUSY` и аппаратные поля I²C. Записи в поля команд, `SOFT_RESET`, I²C и CRC не меняют работу базового тракта. Источник карты регистров — `rdl/tx_regs.rdl`. Изменения карты задаются в RDL и попадают в RTL при генерации.
