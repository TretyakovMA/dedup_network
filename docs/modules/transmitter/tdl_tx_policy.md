# tdl_tx_policy

## Назначение

Соединяет контроллер с четырьмя политиками дедупликации. Выбирает алгоритм, направляет запрос выбранной политике и удерживает владельца транзакции до подтверждения и окончания обслуживания.

## Порты

### Параметры

`DICT_SIZE` задаёт число строк от 2 до 256, по умолчанию 256. `KEY_WIDTH = $clog2(DICT_SIZE)` — производная ширина физического ключа. Обмен и `commit` фиксируются на положительном фронте `clk`. `policy_word` имеет фиксированную ширину 32 бита.

### Тактирование, конфигурация и словарь

| Порт | Направление | Ширина или тип | Назначение |
| --- | --- | --- | --- |
| `clk`, `rst_n` | Вход | По 1 | Общий такт и асинхронный активный низкий сброс. |
| `policy_cfg` | Вход | 32 | Активная конфигурация от CSR-моста, доступна до захвата слова. |
| `valid_bits` | Вход | `DICT_SIZE` | Маска валидности строк, общая для всех алгоритмов. |
| `dict_full` | Вход | 1 | Все физические строки словаря валидны. |
| `next_free_key` | Вход | `KEY_WIDTH` | Минимальный свободный ключ, значим при `dict_full=0`. |
| `aging_done` | Выход | 1 | Импульс завершения обслуживания TinyLFU для статистики. |

### Запрос

| Порт | Направление | Ширина или тип | Назначение |
| --- | --- | --- | --- |
| `policy_req_valid` | Вход | 1 | Controller удерживает запрос, пока policy его не примет. |
| `policy_word` | Вход | 32 | Слово, уже захваченное controller из FIFO. |
| `policy_hit` | Вход | 1 | Результат exact lookup. |
| `policy_hit_key` | Вход | `KEY_WIDTH` | Ключ точного совпадения. Значим только при hit. |
| `policy_req_cfg` | Вход | 32 | Снимок конфигурации для этого слова, зафиксированный при его захвате. |
| `policy_req_ready` | Выход | 1 | Policy готова принять запрос. Handshake: `valid && ready`. |

### Ответ

| Порт | Направление | Ширина или тип | Назначение |
| --- | --- | --- | --- |
| `policy_rsp_valid` | Выход | 1 | Ответ готов. Сохраняется до handshake. |
| `policy_admit` | Выход | 1 | На miss разрешает вставить слово. При hit не определяет тип кадра. |
| `policy_key` | Выход | `KEY_WIDTH` | Ключ для допускаемой вставки/замещения. Используется только при miss и `admit=1`. |
| `policy_bf_filtered` | Выход | 1 | Сохранённый признак отсева BF для подтверждённого события статистики. Для режимов без BF должен быть 0. |
| `policy_rsp_ready` | Вход | 1 | Controller готов принять ответ. Handshake: `valid && ready`. |

### Commit

| Порт | Направление | Ширина или тип | Назначение |
| --- | --- | --- | --- |
| `policy_commit` | Вход | 1 | Controller подтверждает descriptor следующему блоку. Разрешает применить подготовленные изменения метаданных ровно один раз. |

## Логика работы

### Выбор и допуск запроса

Все четыре политики инстанцированы одновременно. `ALGO_SEL` выбирает TinyLFU (`00`), SLRU (`01`), Clock (`10`) или Pure LFU (`11`). При свободном фасаде проверяет активный `policy_cfg` и передаёт готовность выбранной политики в `policy_req_ready`. Инициализация невыбранного TinyLFU не блокирует остальные алгоритмы.

Формат `policy_cfg` задан в `tdl_tx_pkg`. Зарезервированные биты должны равняться 0. Для SLRU требуется `1 <= N_prob < DICT_SIZE`. После захвата слова запрос со снимком `policy_req_cfg` принимается, когда его `ALGO_SEL` и `N_prob` совпадают с активной конфигурацией. Остальные настройки берутся из снимка слова.

### Интерфейс с backend-политиками

| Сигнал контроллера или словаря | Порт выбранного backend | Правило соединения |
| --- | --- | --- |
| `policy_req_valid / policy_req_ready` | `req_valid / req_ready` | Запрос направляется выбранному backend при свободном фасаде и допустимой конфигурации. Handshake контроллера и backend происходят на одном фронте. |
| `policy_hit`, `policy_hit_key` | `req_hit`, `req_hit_key` | Результат точного поиска для сохранённого слова. |
| `valid_bits`, `dict_full`, `next_free_key` | Те же имена | Общие сигналы из словаря. |
| `policy_word` | `req_word` | 32 бита, только TinyLFU. |
| `policy_req_cfg[15:8]` | `req_n_prob` | 8 бит, только SLRU. |
| `policy_req_cfg[2]`, `[3]`, `[4]`, `[31:16]` | `req_cu_disable`, `req_aging_disable`, `req_bf_en`, `req_aging_period` | Сохранённые параметры TinyLFU, захватываются на фронте запроса. |
| `policy_rsp_valid / policy_rsp_ready` | `rsp_valid / rsp_ready` | Ответ возвращает backend, принявший запрос. Handshake ответа общий для контроллера и backend. |
| `policy_admit`, `policy_key` | `rsp_admit`, `rsp_key` | На попадании оба поля равны 0, KEY использует ключ поиска. При отказе в допуске ключ также равен 0. |
| `policy_bf_filtered` | `rsp_bf_filtered` | Передаётся от TinyLFU. В остальных режимах фасад выдаёт 0. |
| `policy_commit` | `commit` | Однотактное подтверждение для backend, ответ которого принял контроллер. |

### Порядок ответа и commit

| Этап | Поведение |
| --- | --- |
| `ST_IDLE` | При готовности выбранной политики принимает запрос и сохраняет её код. |
| `ST_RESPONSE` | Маршрутизирует ответ и `rsp_ready` между контроллером и сохранённой политикой. |
| `ST_WAIT_COMMIT` | После приёма ответа ждёт `policy_commit` и направляет его той же политике. |
| `ST_WAIT_BACKEND` | Ждёт возвращения `req_ready` сохранённой политики, затем возвращается в `ST_IDLE`. |

На попадании контроллер использует ключ точного поиска для KEY. На промахе `policy_admit=1` означает SYNC с выбранным ключом, `policy_admit=0` означает RAW. Данные словаря и подтверждение метаданных обновляются на одном фронте принятия SYNC-дескриптора. При RAW статистические записи TinyLFU тоже могут быть подтверждены по `policy_commit`.

### Готовность после обслуживания TinyLFU

В худшем сценарии второй такт записи BF завершается через один такт после commit. На третьем такте после commit планировщик запускает обход CMS и ротацию BF. Последняя запись CMS выполняется на такте 515. Затем по одному такту занимают подтверждение планировщика, переход TinyLFU в idle и возврат готовности фасада. `policy_req_ready` поднимается на такте 518 после commit. Эта граница лежит в основе программной выдержки по §6.1.1 общей спецификации.

### Связь с контроллером при остановке

Верхний уровень объединяет `policy_req_ready` и `lookup_req_ready` в `backend_ready`. Это удерживает следующий non-Bypass `pop` до обслуживания. Контроллер обходит политику для Bypass-слов. Снятие `TX_EN` останавливает новые захваты, а ранее принятая транзакция сохраняет владельца до завершения.
