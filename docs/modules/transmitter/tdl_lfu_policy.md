# tdl_lfu_policy

## Назначение

Реализует Pure LFU (`ALGO_SEL=2'b11`). Ведёт локальную частоту обращений к каждой строке и при полном словаре выбирает строку с наименьшей частотой.

## Порты

### Параметры

`DICT_SIZE` задаёт число строк от 2 до 256, по умолчанию 256. `KEY_WIDTH = $clog2(DICT_SIZE)` — производная ширина физического ключа. Обмен и `commit` фиксируются на положительном фронте `clk`.

| Порт | Направление | Ширина или тип | Назначение |
| --- | --- | --- | --- |
| `clk` | Вход | 1 | Общий такт TX. Обмен и commit фиксируются по положительному фронту. |
| `rst_n` | Вход | 1 | Общий сброс, активный низким уровнем. |
| `req_valid` | Вход | 1 | `tdl_tx_policy` выставляет запрос выбранному backend. |
| `req_ready` | Выход | 1 | Backend свободен и может принять одно слово. |
| `req_hit` | Вход | 1 | Результат точного поиска для принятого слова. |
| `req_hit_key` | Вход | `KEY_WIDTH` | Ключ совпавшей валидной строки при `req_hit=1`. |
| `valid_bits` | Вход | `DICT_SIZE` | Маска строк из storage через `tdl_dict_unit`. Бит `i` относится к физическому ключу `i`. |
| `dict_full` | Вход | 1 | Все физические строки заняты. |
| `next_free_key` | Вход | `KEY_WIDTH` | Минимальный свободный ключ. Значим только при `dict_full=0`. |
| `rsp_valid` | Выход | 1 | Решение и подготовленные изменения готовы. |
| `rsp_ready` | Вход | 1 | `tdl_tx_policy` может передать этот ответ контроллеру. |
| `rsp_admit` | Выход | 1 | 1 разрешает вставку при промахе. При попадании значение 0. |
| `rsp_key` | Выход | `KEY_WIDTH` | Физический ключ вставки/замены при промахе с `rsp_admit=1`. В остальных случаях значение 0. |
| `commit` | Вход | 1 | Однотактный `policy_commit`, направленный фасадом выбранному backend после приёма ответа. |

## Логика работы

### Локальная частота

Каждой строке соответствует четырёхбитный `local_cnt[i]` с насыщением на 15. При сбросе счётчики обнуляются. При подтверждённом попадании счётчик строки увеличивается на единицу, пока не достигнет 15. При вставке или замене счётчик выбранной строки устанавливается в 1 для нового слова.

### Выбор строки

При промахе в неполном словаре `rsp_key = next_free_key`. При промахе в полном словаре комбинационное дерево сравнивает локальные счётчики валидных строк и возвращает индекс минимального значения. При равенстве выбирается меньший ключ. Политика допускает любой промах, поэтому контроллер формирует SYNC. При попадании контроллер формирует KEY с ключом поиска.

### Ответ и обновление

Ключ и признак вставки фиксируются на фронте `req_valid && req_ready`. Ответ доступен сразу после этого фронта и удерживается до `rsp_valid && rsp_ready`. Счётчики обновляются на последующем `commit`. До подтверждения политика не принимает новое слово. После сброса начатая операция отменяется.

Счётчики относятся к текущим словам словаря. Управление периодическим aging применяется к TinyLFU. Bypass обходит Pure LFU и формирует RAW.
