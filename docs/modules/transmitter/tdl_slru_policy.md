# tdl_slru_policy

## Назначение

Реализует Segmented LRU (`ALGO_SEL=2'b01`). Делит валидные строки словаря на сегменты Probationary и Protected, поддерживает LRU-порядок в каждом и выбирает строку для вставки или замещения.

## Порты

### Параметры

`DICT_SIZE` задаёт число строк от 2 до 256, по умолчанию 256. `KEY_WIDTH = $clog2(DICT_SIZE)` — производная ширина физического ключа. Обмен и `commit` фиксируются на положительном фронте `clk`.

| Порт | Направление | Ширина или тип | Назначение |
| --- | --- | --- | --- |
| `clk` | Вход | 1 | Общий такт TX. Обмен и commit фиксируются по положительному фронту. |
| `rst_n` | Вход | 1 | Общий сброс, активный низким уровнем. |
| `req_valid` | Вход | 1 | `tdl_tx_policy` выставляет запрос выбранному backend. |
| `req_ready` | Выход | 1 | Backend свободен и может принять одно слово. |
| `req_hit` | Вход | 1 | Результат точного поиска для принятого слова. |
| `req_hit_key` | Вход | `KEY_WIDTH` | Ключ совпавшей валидной строки при `req_hit=1`. |
| `req_n_prob` | Вход | 8 | Квота Probationary в строках из `policy_req_cfg[15:8]`. Используется на фронте приёма запроса. |
| `valid_bits` | Вход | `DICT_SIZE` | Маска строк из storage через `tdl_dict_unit`. Бит `i` относится к физическому ключу `i`. |
| `dict_full` | Вход | 1 | Все физические строки заняты. |
| `next_free_key` | Вход | `KEY_WIDTH` | Минимальный свободный ключ. Значим только при `dict_full=0`. |
| `rsp_valid` | Выход | 1 | Решение и подготовленные изменения готовы. |
| `rsp_ready` | Вход | 1 | `tdl_tx_policy` может передать этот ответ контроллеру. |
| `rsp_admit` | Выход | 1 | 1 разрешает вставку при промахе. При попадании значение 0. |
| `rsp_key` | Выход | `KEY_WIDTH` | Физический ключ вставки/замены при промахе с `rsp_admit=1`. В остальных случаях значение 0. |
| `commit` | Вход | 1 | Однотактный `policy_commit`, направленный фасадом выбранному backend после приёма ответа. |

## Логика работы

### Квоты и ранги

`N_prob = req_n_prob` задаёт квоту Probationary, `N_prot = DICT_SIZE - N_prob` — квоту Protected. Допустимо `1 <= N_prob < DICT_SIZE`. Значение `SLRU_CFG_REG=0x40` при `DICT_SIZE=256` даёт квоты 64 и 192. Например, при `DICT_SIZE=2` программно надо задать `N_prob=1` до первого извлечения слова.

Каждая строка имеет тег сегмента и ранг. Ранг 0 означает MRU, наибольший ранг среди валидных строк сегмента — LRU. Группа рангов в каждом сегменте непрерывна. Два комбинационных дерева выбирают LRU каждого сегмента. Занятость непустого сегмента равна его максимальному рангу плюс один.

### Попадание и границы сегментов

При попадании в Protected строка становится MRU своего сегмента. При попадании в Probationary строка переносится в MRU Protected. Если Protected заполнен, его LRU переходит в MRU Probationary на место по квоте, освободившееся при переносе. Ранги остальных строк обновляются, чтобы порядок оставался непрерывным. Физические ключи и слова на hit сохраняются, поэтому контроллер формирует KEY с ключом точного поиска.

### Промах и выбор строки

Если в Probationary осталась квота, используется `next_free_key`. Если Probationary заполнен, выбирается его LRU даже при `dict_full=0`. Например, при квоте Probationary 2 последовательность из трёх разных слов без попаданий вытесняет первое из Probationary, хотя в Protected могут оставаться свободные строки. Вставленная или заменённая строка становится MRU Probationary. Контроллер выдаёт SYNC с `rsp_key` и записывает слово по этому ключу на commit.

### Ответ и commit

На фронте приёма запроса запоминаются действие, ключи и исходный ранг, необходимый при попадании. `rsp_valid` поднимается после этого фронта и удерживается до приёма ответа. Новый запрос допускается после `commit`. На фронте `commit` теги и ранги изменяются параллельно. При сбросе теги и ранги обнуляются, а актуальная валидность строк берётся из хранилища по `valid_bits`.
