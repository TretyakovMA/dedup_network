# tdl_parallel_search

## Назначение

Находит точное совпадение входного слова среди валидных строк словаря и возвращает минимальный совпавший индекс. Используется как комбинационная часть `tdl_dict_unit`.

## Порты

### Параметры

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `DATA_WIDTH` | 32 | Ширина искомого и хранимого слова. |
| `DICT_SIZE` | 256 | Количество сравниваемых строк. |
| `KEY_WIDTH` | `$clog2(DICT_SIZE)` | Локальная ширина выходного индекса `hit_index`. |

В передатчике `DICT_SIZE` лежит в диапазоне 2…256. Сравнение вычисляется для индексов от 0 до `DICT_SIZE-1`, в том числе при размере, отличном от степени двойки.

Результат зависит от текущих значений входов. Тактирование и сброс отсутствуют.

| Порт | Направление | Ширина или тип | Назначение |
| --- | --- | --- | --- |
| `search_word` | Вход | `DATA_WIDTH` | Слово, которое нужно найти в словаре. |
| `dict_words` | Вход | `DICT_SIZE × DATA_WIDTH` | Текущие слова массива. Элемент `dict_words[i]` соответствует строке `i`. |
| `valid_bits` | Вход | `DICT_SIZE` | Маска валидности строк. Строка участвует в сравнении только при `valid_bits[i]=1`. |
| `hit` | Выход | 1 | Равен 1, если найдено хотя бы одно точное совпадение. |
| `hit_index` | Выход | `KEY_WIDTH` | Индекс выбранной совпавшей строки. Имеет смысл только при `hit=1`. |

## Логика работы

### Сравнение и выбор индекса

Для каждой строки `i` вычисляется совпадение:

```text
match_vector[i] = valid_bits[i] && (dict_words[i] == search_word)
hit             = OR(match_vector)
```

Затем приоритетный кодировщик просматривает `match_vector` от младшего индекса к старшему. При первом установленном бите он возвращает `i` в `hit_index`. Поэтому при нескольких совпадениях результатом будет **минимальный индекс**.

Если совпадений нет, `hit=0`, а `hit_index=0` из-за значения по умолчанию в кодере. Потребитель использует `hit_index` только при `hit=1`. Данные невалидных строк могут совпадать со словом, но эти строки исключены маской.

Пара `hit/hit_index` не регистрируется. Если `search_word`, `dict_words` или `valid_bits` изменятся, выходы изменятся после комбинационной задержки логики. Источник должен удерживать входы достаточно долго для корректного захвата результата потребителем.

### Подключение к словарю

Хранилище `tdl_dict_storage` подаёт `dict_words` и `valid_bits`. `tdl_dict_unit` соединяет `search_data` с `search_word` и при принятии запроса регистрирует `hit` и `hit_index` как ответ `lookup_hit` и `lookup_key`. Запрос на фронте записи видит старые данные. Запросы с последующих фронтов учитывают обновлённую строку.

### Пример

Для `DICT_SIZE=4`, `search_word=32'h1234_5678` и состояния:

| Индекс | `valid_bits[i]` | `dict_words[i]` | `match_vector[i]` |
| ---: | ---: | --- | ---: |
| 0 | 1 | `32'hAAAA_0000` | 0 |
| 1 | 0 | `32'h1234_5678` | 0 |
| 2 | 1 | `32'h1234_5678` | 1 |
| 3 | 1 | `32'h1234_5678` | 1 |

Результат: `hit=1`, `hit_index=2`. Строка 1 игнорируется из-за `valid_bits[1]=0`. Из совпадений в строках 2 и 3 выбирается меньший индекс.
