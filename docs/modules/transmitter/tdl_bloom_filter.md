# tdl_bloom_filter

## Назначение

Фильтр Блума хранит два поколения отпечатков промахов TinyLFU по 4096 бит каждое. По паре хэш-адресов определяет, наблюдалось ли слово ранее, и по `commit` регистрирует наблюдение в активном поколении. Результат управляет допуском к CMS. Точное совпадение слова определяет словарь.

## Порты

| Порт | Направление | Ширина или тип | Назначение |
| --- | --- | --- | --- |
| `clk`, `rst_n` | Вход | По 1 | Такт и активный низкий reset. |
| `req_valid` | Вход | 1 | Запрос TinyLFU для exact miss при BF_EN=1. |
| `req_ready` | Выход | 1 | Можно принять запрос. |
| `req_h0`, `req_h1` | Вход | По 12 | h_bf1/h_bf2 одного слова. |
| `rsp_valid` | Выход | 1 | Результат проверки готов. |
| `rsp_ready` | Вход | 1 | TinyLFU готов принять результат. |
| `rsp_seen` | Выход | 1 | Оба адреса присутствуют в объединении поколений. |
| `commit` | Вход | 1 | Однократная установка битов после приёма ответа. |
| `rotate_req` | Вход | 1 | Однотактный запрос ротации при свободном BF. |
| `rotate_done` | Выход | 1 | Однотактное завершение ротации. |
| `busy` | Выход | 1 | Инициализация, запрос, ожидание commit, запись или ротация выполняются. |

## Логика работы

### Ответ и подтверждение записи

Адреса захватываются при req_valid && req_ready. Источник удерживает запрос до handshake. По состоянию до установки текущих битов вычисляется

```text
rsp_seen = (active[req_h0] || old[req_h0])
        && (active[req_h1] || old[req_h1])
```

При `rsp_valid && !rsp_ready` ответ сохраняется. После handshake ответа модуль удерживает адреса, а `req_ready` остаётся равным 0 до завершения записи. `commit` запускает установку обоих битов в active при любом `rsp_seen`. При одинаковых адресах устанавливается один физический бит.

`rsp_seen=0` приводит к RAW с отсевом BF. `rsp_seen=1` разрешает запрос CMS. Коллизия адресов может пропустить в CMS ещё не встречавшееся слово. KEY по-прежнему требует полного совпадения слов.

Commit без ожидающего подтверждения запроса и повторный commit являются ошибками протокола.

Физическое поколение хранится в синхронном банке из 128 слов по 32 бита. На фронте приёма запроса читается слово первого хэша из обоих банков. На следующем фронте читается слово второго хэша. Ещё через такт выставляется `rsp_valid`. Запись первого слова выполняется на фронте `commit`. Хэши в одном слове объединяются в одну запись. Для разных слов второе записывается на следующем фронте. `busy` остаётся активным до завершения записи.

### Ротация поколений

[tdl_aging_ctrl](tdl_aging_ctrl.md) выдаёт rotate_req после подтверждения обычных записей слова через word_updates_done. Модуль очищает физический old-буфер, затем меняет роли поколений. Бывший active становится old, очищенный буфер становится active.

rotate_req имеет приоритет перед новым запросом и снимает req_ready. Клиент выдаёт один импульс и ждёт rotate_done. Очистка занимает 128 тактов после приёма запроса. На фронте последней записи меняются роли банков и выставляется однотактный `rotate_done`.

### Начальная очистка и выключение BF

Reset сбрасывает управляющее состояние. В reset `req_ready`, `rsp_valid` и `rotate_done` равны 0. После снятия reset оба банка очищаются параллельно по одному слову за такт. `busy` остаётся активным до окончания инициализации через 128 тактов.

`BF_EN` декодирует TinyLFU. При `BF_EN=0` модуль сохраняет оба поколения без новых запросов и ротаций. При включённом BF периодическую ротацию назначает `tdl_aging_ctrl` независимо от `AGING_DISABLE`.
