# tdl_clock_policy

## Назначение

Реализует Clock (`ALGO_SEL=2'b10`). Хранит бит второго шанса для каждой строки и кольцевой указатель. При промахе выбирает свободную строку либо находит кандидата на замену кольцевым обходом.

## Порты

### Параметры

`DICT_SIZE` задаёт число строк от 2 до 256, по умолчанию 256. `KEY_WIDTH = $clog2(DICT_SIZE)` — производная ширина физического ключа. Обмен и `commit` фиксируются на положительном фронте `clk`.

| Порт | Направление | Ширина или тип | Назначение |
| --- | --- | --- | --- |
| `clk` | Вход | 1 | Общий такт TX. Обмен и commit фиксируются по положительному фронту. |
| `rst_n` | Вход | 1 | Общий сброс, активный низким уровнем. |
| `req_valid` | Вход | 1 | `tdl_tx_policy` выставляет запрос выбранному backend. |
| `req_ready` | Выход | 1 | Backend свободен и может принять одно слово. |
| `req_hit` | Вход | 1 | Результат точного поиска для принятого слова. |
| `req_hit_key` | Вход | `KEY_WIDTH` | Ключ совпавшей валидной строки при `req_hit=1`. |
| `valid_bits` | Вход | `DICT_SIZE` | Маска строк из storage через `tdl_dict_unit`. Бит `i` относится к физическому ключу `i`. |
| `dict_full` | Вход | 1 | Все физические строки заняты. |
| `next_free_key` | Вход | `KEY_WIDTH` | Минимальный свободный ключ. Значим только при `dict_full=0`. |
| `rsp_valid` | Выход | 1 | Решение и подготовленные изменения готовы. |
| `rsp_ready` | Вход | 1 | `tdl_tx_policy` может передать этот ответ контроллеру. |
| `rsp_admit` | Выход | 1 | 1 разрешает вставку при промахе. При попадании значение 0. |
| `rsp_key` | Выход | `KEY_WIDTH` | Физический ключ вставки/замены при промахе с `rsp_admit=1`. В остальных случаях значение 0. |
| `commit` | Вход | 1 | Однотактный `policy_commit`, направленный фасадом выбранному backend после приёма ответа. |

## Логика работы

### Попадание и свободная строка

Бит `usage_bit[i]` обозначает, что строке `i` положен второй шанс при обходе. `clock_hand` задаёт начало обхода. При попадании выставляется `usage_bit[req_hit_key]`. При промахе и `dict_full=0` политика возвращает `rsp_admit=1` и `rsp_key=next_free_key`, а при подтверждении ставит бит новой строки. В обоих случаях `clock_hand` сохраняется.

### Кольцевой обход полного словаря

При полном словаре поиск начинается с `clock_hand` и проверяет одну строку за такт. Для строки с установленным битом политика отмечает его очистку в рабочей маске `clear_mask` и переходит к следующему ключу. Строка с исходным нулевым битом или с битом, уже отмеченным к очистке, выбирается для замены. После ключа `DICT_SIZE-1` обход переходит к нулю, в том числе при размере словаря, отличном от степени двойки.

При всех установленных битах обход отмечает очистку всех `DICT_SIZE` строк и возвращается к стартовой. На `commit` отмеченные биты очищаются, бит строки замены устанавливается в 1, а `clock_hand` переходит к следующей строке.

### Ответ и подтверждение

При hit и при свободной вставке `rsp_valid` поднимается сразу после фронта приёма запроса. При полном словаре ответ появляется через 1…`DICT_SIZE+1` тактов. Ключ ответа на промахе становится ключом SYNC. При hit контроллер выбирает ключ из результата точного поиска.

До `rsp_valid && rsp_ready` ответ удерживается. Затем политика ждёт `commit`, который применяет обновления ровно один раз. По сбросу биты второго шанса и указатель обнуляются, незавершённый запрос отменяется. В Bypass фасад не вызывает политику для новых слов.

### Пример обхода

Если `DICT_SIZE=3`, рука указывает на 1, а биты строк 0, 1 и 2 равны 1, обход отмечает очистку строк 1, 2 и 0. Следующая проверка строки 1 выбирает её для замены. После `commit` биты строк 0 и 2 равны 0, бит строки 1 равен 1, рука указывает на 2.
