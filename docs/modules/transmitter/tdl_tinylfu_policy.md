# tdl_tinylfu_policy

## Назначение

Реализует TinyLFU (`ALGO_SEL=2'b00`). По результату точного поиска обновляет локальную статистику попадания либо применяет фильтр Блума и CMS при промахе. При допуске нового слова возвращает физический ключ вставки или замены.

## Порты

### Параметры

`DICT_SIZE` задаёт число строк от 2 до 256, по умолчанию 256. `KEY_WIDTH = $clog2(DICT_SIZE)` — производная ширина физического ключа. Обмен и `commit` фиксируются на положительном фронте `clk`.

| Порт | Направление | Ширина или тип | Назначение |
| --- | --- | --- | --- |
| `clk` | Вход | 1 | Общий такт TX. Обмен и commit фиксируются по положительному фронту. |
| `rst_n` | Вход | 1 | Общий сброс, активный низким уровнем. |
| `req_valid` | Вход | 1 | `tdl_tx_policy` выставляет запрос выбранному backend. |
| `req_ready` | Выход | 1 | Backend свободен и может принять одно слово. |
| `req_hit` | Вход | 1 | Результат точного поиска для принятого слова. |
| `req_hit_key` | Вход | `KEY_WIDTH` | Ключ совпавшей валидной строки при `req_hit=1`. |
| `req_word` | Вход | 32 | Сохранённое слово `policy_word` для хэширования на промахе. |
| `req_cu_disable` | Вход | 1 | `policy_req_cfg[2]`. 1 выбирает standard update CMS. |
| `req_aging_disable` | Вход | 1 | `policy_req_cfg[3]`. 1 отключает деление счётчиков. |
| `req_bf_en` | Вход | 1 | `policy_req_cfg[4]`. 1 разрешает проверку, установку битов и ротацию BF. |
| `req_aging_period` | Вход | 16 | `policy_req_cfg[31:16]`. Период в подтверждённых словах TinyLFU. |
| `valid_bits` | Вход | `DICT_SIZE` | Маска строк из storage через `tdl_dict_unit`. Бит `i` относится к физическому ключу `i`. |
| `dict_full` | Вход | 1 | Все физические строки заняты. |
| `next_free_key` | Вход | `KEY_WIDTH` | Минимальный свободный ключ. Значим только при `dict_full=0`. |
| `rsp_valid` | Выход | 1 | Решение и подготовленные изменения готовы. |
| `rsp_ready` | Вход | 1 | `tdl_tx_policy` может передать этот ответ контроллеру. |
| `rsp_admit` | Выход | 1 | 1 разрешает вставку при промахе. При попадании значение 0. |
| `rsp_key` | Выход | `KEY_WIDTH` | Физический ключ вставки/замены при промахе с `rsp_admit=1`. В остальных случаях значение 0. |
| `rsp_bf_filtered` | Выход | 1 | 1 только для промаха, отвергнутого включённым BF. Во всех остальных ответах 0. |
| `commit` | Вход | 1 | Однотактный `policy_commit`, направленный фасадом выбранному backend после приёма ответа. |
| `aging_done` | Выход | 1 | Однотактное подтверждение конца обслуживания для статистики. Фасад передаёт его независимо от канала ответа слова. |

## Логика работы

### Выбор действия для слова

Фасад подаёт поиск и снимок настроек слова на `req_*`. Ответ остаётся действительным до `rsp_valid && rsp_ready`. Политика различает следующие случаи.

| Условие | Действие | Кадр от контроллера |
| --- | --- | --- |
| Точное попадание | Подготовить увеличение локального счётчика совпавшей строки. Hash, BF и CMS для этого слова не вызываются. | KEY с ключом поиска. |
| Промах, включённый BF вернул `rsp_seen=0` | Вернуть `rsp_admit=0` и `rsp_bf_filtered=1`. На `commit` установить биты BF. | RAW. |
| Промах после BF pass или при выключенном BF, есть свободная строка | Получить `f_new` из CMS и вернуть `rsp_admit=1`, `rsp_key=next_free_key`. | SYNC в свободную строку. |
| Промах после BF pass или при выключенном BF, словарь полон | Найти минимальный локальный счётчик `f_min` среди валидных строк. При равном минимуме выбирается меньший ключ. Допустить замену только при `f_new > f_min`. | SYNC при допуске, RAW при равенстве или меньшей оценке. |

`f_new` — минимум двух счётчиков CMS после учёта подготовленного обновления. Статистика CMS относится ко всем промахам, дошедшим до CMS, включая отказы при сравнении частот.

### Пример повторного слова

Если словарь пуст, BF включён, а оба поколения очищены, первое появление слова даёт промах BF и RAW. После `commit` оба адреса записаны в active. Если между обращениями история BF сохраняется, второй промах получает оценку CMS и допускается в свободную строку с выдачей SYNC. Следующий поиск находит точное совпадение и даёт KEY с этим же ключом.

### Связи с hash, BF, CMS и aging

| Потребитель | Данные от TinyLFU | Результат и подтверждение |
| --- | --- | --- |
| [tdl_tab_hash](tdl_tab_hash.md) | `in_valid` и `data_in=req_word` после точного промаха | Запрос принят при `in_valid && in_ready`. При `out_valid && out_ready` TinyLFU захватывает вместе `h_bf1/h_bf2` по 12 бит и `h_cms1/h_cms2` по 8 бит. |
| [tdl_bloom_filter](tdl_bloom_filter.md) | `req_h0=h_bf1` и `req_h1=h_bf2` по 12 бит при `req_bf_en=1` | TinyLFU принимает `rsp_seen` по `valid/ready` и передаёт `commit` для каждого слова, получившего результат BF. Адреса удерживает фильтр. |
| [tdl_cms](tdl_cms.md) | `req_valid`, `req_h0=h_cms1`, `req_h1=h_cms2` и `req_cu_disable` для промаха после BF pass или при выключенном BF | При `rsp_valid && rsp_ready` TinyLFU захватывает `rsp_est[3:0]` как `f_new`. На внешнем `commit` посылает один импульс `tdl_cms.commit`, если слово ранее получило ответ CMS. |
| [tdl_aging_ctrl](tdl_aging_ctrl.md) | `word_commit` на каждом `commit` TinyLFU, сохранённые `req_aging_period`, `req_aging_disable`, `req_bf_en` и уровень `word_updates_done` | Планировщик запускает операции после обычных записей слова. Для CMS подключены `aging_req/aging_done`, для BF — `rotate_req/rotate_done`, для локальных счётчиков — запрос и подтверждение их деления. Сводный `aging_done` завершает обслуживание backend. |

### Подтверждение и локальные счётчики

Политика применяет подготовленные изменения после `commit`. Вставленная строка получает локальный счётчик 1. При попадании локальный счётчик увеличивается с насыщением на 15. BF подтверждает запись для каждого промаха, прошедшего через BF, включая первый отфильтрованный промах. CMS подтверждает запись для каждого промаха, получившего оценку, независимо от принятого решения о вставке.

### Обслуживание между словами

`tdl_aging_ctrl` учитывает каждый подтверждённый KEY, RAW и SYNC TinyLFU. При `req_aging_period=0` периодическое обслуживание отключено. На границе периода он ждёт конца обычных записей текущего слова. Затем при `req_aging_disable=0` делит локальные счётчики и таблицу CMS на два с округлением вниз, а при `req_bf_en=1` запускает ротацию BF. `aging_done` подтверждает завершение всех назначенных операций.

Новый запрос блокируется до завершения обычных записей и обслуживания. После общего сброса BF очищает оба поколения, CMS — обе строки таблицы, а локальные частоты обнуляются. При выборе TinyLFU контроллер ждёт готовности этого backend до извлечения нового слова.
