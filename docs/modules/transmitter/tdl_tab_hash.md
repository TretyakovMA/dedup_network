# tdl_tab_hash

## Назначение

Вычисляет четыре индекса статистики TinyLFU по 32-битному слову. При точном промахе два индекса адресуют биты фильтра Блума, ещё два — счётчики в разных строках CMS.

## Порты

| Порт | Направление | Ширина или тип | Назначение |
| --- | --- | --- | --- |
| `clk` | Вход | 1 | Общий такт TX. Обмен фиксируется по положительному фронту. |
| `rst_n` | Вход | 1 | Общий сброс, активный низким уровнем. Очищает `out_valid`. |
| `in_valid` | Вход | 1 | TinyLFU передаёт слово после точного промаха. |
| `in_ready` | Выход | 1 | В выходном регистре есть место для результата. |
| `data_in` | Вход | 32 | Исходное слово из `req_word` TinyLFU. |
| `out_valid` | Выход | 1 | Все четыре индекса одного слова готовы. |
| `out_ready` | Вход | 1 | TinyLFU готов принять все четыре индекса одним фронтом. |
| `h_bf1` | Выход | 12 | Первый адрес BF. |
| `h_bf2` | Выход | 12 | Второй адрес BF. |
| `h_cms1` | Выход | 8 | Адрес столбца в строке 0 CMS, подаётся на `req_h0` CMS. |
| `h_cms2` | Выход | 8 | Адрес столбца в строке 1 CMS, подаётся на `req_h1` CMS. |

## Логика работы

### Табличная функция

Входное 32-битное слово раскладывается на четыре байта:

```text
X = {B3, B2, B1, B0}
h_i(X) = T[i,3][B3] XOR T[i,2][B2] XOR T[i,1][B1] XOR T[i,0][B0]
```

Для каждой hash-функции `i` и каждой байтовой позиции хранится таблица из 256 констант ширины `W`. Для любого байта это одна табличная выборка. Четыре результата объединяются XOR-ом.

Четыре выхода используют отдельные наборы таблиц.

| Функция | Потребитель | Ширина | Диапазон |
| --- | --- | ---: | --- |
| `h_bf1` | Первый BF адрес | 12 бит | 0…4095 |
| `h_bf2` | Второй BF адрес | 12 бит | 0…4095 |
| `h_cms1` | Адрес столбца CMS row 0 | 8 бит | 0…255 |
| `h_cms2` | Адрес столбца CMS row 1 | 8 бит | 0…255 |

Для каждой функции и позиции байта генератор задаёт отдельную детерминированную таблицу. В симуляции и синтезе используются одни и те же константы ROM. RTL package фиксирует seed `32'h5444_4C06`, версию набора `2`, порядок заполнения от байта `0` до `255` и 32-битное смешивание с константами `85EB_CA6B` и `C2B2_AE35`.

Генератор и константы выделены в [tdl_tab_hash_pkg](tdl_tab_hash_pkg.md). Пакет компилируется перед модулем, его объявления импортируются внутри tdl_tab_hash.

### Захват и выдача

`in_ready = rst_n && (!out_valid || out_ready)`. Слово принимается на фронте T0 при `in_valid && in_ready`. Сразу после T0 индексы находятся в выходном регистре. Следующий фронт T1 — самый ранний момент их приёма при `out_valid && out_ready`. Выдача старого результата и приём нового слова на одном фронте позволяют обрабатывать одно слово за такт.

При `in_valid=1, in_ready=0` источник удерживает слово и `in_valid`. При `out_valid=1, out_ready=0` модуль удерживает все индексы и `out_valid`. После сброса данные выхода значимы со следующим `out_valid`. Жизненный цикл хэша заканчивается на handshake выхода. Подтверждение изменения статистики проходит отдельно через TinyLFU и CMS.

### Роль коллизий

Разные слова могут адресовать одни и те же биты BF или счётчики CMS. Это может пропустить новое слово через BF или завысить оценку частоты. KEY формируется только по точному сравнению исходного слова со словарём. Хэш-адреса используются в статистике и не кодируются в кадр.
