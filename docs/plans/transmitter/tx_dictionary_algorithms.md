# Словарь дедупликации и политики передатчика

Документ раскрывает раздел 4.2 [базового плана передатчика](tx_baseline_plan.md): описывает границы модулей, владение состоянием, путь слова через поиск и политику, а также варианты вытеснения. Целевая архитектура сверена с текущей [спецификацией](../../spec.md) и RTL.

## 1. Статус и область действия

Словарь хранит пары «ключ → 32-битное слово». При точном совпадении передатчик может выдать короткий кадр `KEY`; при вставке или замене записи он выдаёт `SYNC`, а если слово не допускается в словарь — `RAW`. Форматы этих кадров определены в спецификации, §4.1.

Сейчас реализованы базовые массивы слов и valid-битов, параллельный точный поиск и объединяющий их `tdl_dict_unit`. Политики вытеснения и admission, BF, CMS и планируемый общий интерфейс policy описаны как архитектура следующих этапов, а не как уже подключенная функциональность. Существующий `tdl_tx_top` пока не инстанцирует словарь; его controller использует более ранний интерфейс `dict_hit/dict_key/force_sync`. Текущая реализация `tdl_tx_controller` уже описывает новый поток запросов поиска/policy и commit, но сама также не подключена к top. См. фактические файлы [tdl_tx_top.sv](../../../rtl/transmitter/tdl_tx_top.sv), [tdl_tx_controller.sv](../../../rtl/transmitter/tdl_tx_controller.sv) и [tdl_dict_unit.sv](../../../rtl/transmitter/tdl_dict_unit.sv).

## 2. Словарь терминов

| Термин | Значение |
| --- | --- |
| **Словарь** | `DICT_SIZE` физических строк, каждая хранит 32-битное слово и признак валидности. В базовой версии `DICT_SIZE` лежит в диапазоне 2…256. |
| **Строка / entry** | Физическая ячейка массива с индексом `0 … DICT_SIZE-1`. Слово остаётся в этой строке до записи нового слова или очистки valid-бита. |
| **Ключ / key** | Индекс строки словаря. Внутренняя ширина `KEY_WIDTH = $clog2(DICT_SIZE)`. В кадрах ключ передаётся байтом; controller расширяет его нулями до 8 бит. Проверка `key < DICT_SIZE` обязательна, в том числе для размеров словаря, не являющихся степенью двойки. |
| **valid-бит** | Отмечает, содержит ли строка слово, участвующее в поиске. Неинициализированное или очищенное слово не считается совпадением независимо от содержимого массива данных. |
| **Hit / попадание** | Найдена валидная строка, чьё 32-битное содержимое в точности равно входному слову. Результат — ключ этой строки. |
| **Miss / промах** | Ни одна валидная строка не равна входному слову. Политика решает, передать слово как `RAW` или записать его и передать `SYNC`. |
| **Свободная строка** | Строка с `valid=0`. Используется прежде вытеснения, если это допускает квота алгоритма; SLRU не заимствует свободную квоту Protected. |
| **Кандидат / victim** | Валидная строка, выбранная политикой для замены при полном словаре. Кандидат определяется алгоритмом, а не хранилищем. |
| **Admission** | Решение, стоит ли добавлять новое слово после промаха. Например, TinyLFU может отказать и выбрать `RAW`, даже когда словарь заполнен и кандидат найден. |
| **Метаданные политики** | Состояние, используемое только для выбора и обновления политики: usage-биты, счётчики частоты, сегмент и порядок возраста, либо таблицы BF/CMS. Это не содержимое словаря. |
| **Descriptor / дескриптор** | Зафиксированное решение для кадра: тип (`RAW`, `KEY`, `SYNC`), байтовый ключ и исходное слово. Потребитель — frame buffer/serializer. |
| **Commit** | Событие `desc_valid && desc_ready`: следующий блок гарантированно принимает дескриптор. Запись словаря для `SYNC` и подготовленные изменения policy фиксируются на этом подтверждении ровно один раз. Commit не означает, что кадр уже передан по SDR. |

## 3. Владение модулями и состоянием

Целевой путь имеет вид:

```text
tdl_tx_top
├── входной FIFO ── слово ──> tdl_tx_controller
├── tdl_dict_unit
│   ├── tdl_parallel_search ── hit/key ──> controller
│   └── tdl_dict_storage <── запись SYNC / состояние строк
└── tdl_tx_policy <── запрос слова + результат поиска + конфигурация
    ├── выбранная policy: Clock / LFU / SLRU / TinyLFU
    └── TinyLFU backend: tab hash + BF + CMS + aging

controller ── descriptor ──> frame buffer ──> serializer
```

Верхний уровень соединяет блоки и регистровые настройки. Он не содержит алгоритмический поиск или правила вытеснения. Пакет `tdl_tx_pkg` определяет общие типы/коды, но не хранит аппаратное состояние.

| Блок | Единоличный владелец | Что ему принадлежит | Что он не решает |
| --- | --- | --- | --- |
| `tdl_dict_storage` | Физический массив словаря | `dict_words`, `valid_bits`, очистка, запись строки, число занятых строк, `dict_full`, индекс свободной строки | Hit/miss, политика вытеснения, BF/CMS, тип кадра |
| `tdl_parallel_search` | Только вычисление результата поиска | Комбинационные сравнения и кодирование ключа совпадения | Состояние словаря, запись, admission, метаданные replacement |
| `tdl_dict_unit` | Интеграционный фасад словаря | Соединение storage/search, выбор индекса для команды записи, выдача статусов словаря | Выбор кандидата занятой строки и обновление policy |
| `tdl_tx_policy` | Оркестратор политик | Выбор алгоритма по зафиксированной конфигурации, запуск backend, удержание ответа до handshake/commit | Владение массивом слов; выдача/передача SDR-битов |
| `tdl_clock_policy` | Метаданные Clock | usage-биты и рука Clock; сканирование кандидата и подготовка изменений битов | Физическая запись слова или объявление hit |
| `tdl_lfu_policy` | Локальные счётчики Pure LFU | Частота каждой строки, поиск минимума и обновление hit/insert | Глобальная частота слов, BF/CMS, содержимое строки |
| `tdl_slru_policy` | Метаданные сегментного LRU | Принадлежность строк сегментам, возраст/LRU, promote/demote и выбор probationary victim | Физическое перемещение данных между индексами; поиск равенства слов |
| `tdl_tinylfu_policy` | Решение admission и локальная частота TinyLFU | Вызовы BF/CMS и сравнение `f_new` с частотами resident entries; подготовка `admit` и victim | Таблицы BF/CMS, физическое хранение слова, сериализация |
| `tdl_tab_hash` | Хэш-адреса для TinyLFU | Хэш-индексы BF и CMS, рассчитанные из слова | Решение о совпадении слова в словаре или выбор кадра |
| `tdl_bloom_filter` | Два поколения BF | Биты `active/old`, проверка принадлежности, установка битов, ротация/очистка поколения | Точное подтверждение наличия слова; BF допускает коллизии |
| `tdl_cms` | Таблица оценки частот TinyLFU | Две строки счётчиков, conservative/standard update, насыщение и aging | Точный подсчёт каждого слова или выбор строки словаря |
| `tdl_aging_ctrl` | Планировщик обслуживания статистики | Счётчик слов/периода, запрос обслуживания, ожидание конца очистки/aging и `aging_done` | Самостоятельное изменение слова/ключа или решение admission |
| `tdl_tx_controller` | Транзакция одного входного слова и descriptor | Захваченное слово и конфигурация, FSM запросов, выбор `RAW/KEY/SYNC`, ожидание места и единственный commit | Алгоритм кандидата, содержимое массива, передача битов |
| `tdl_tx_frame_buffer` | Один ожидающий descriptor | Valid и поля descriptor до приёма serializer | Дополнительное обновление словаря или сигнал завершения SDR-кадра |

### 3.1. Единственный источник истины для каждой категории

- Физические данные и valid-статус строки существуют только в `tdl_dict_storage`. Policy не копирует и не переставляет слова.
- Результат exact lookup вычисляет `tdl_parallel_search`; политика принимает его как вход и не подменяет точное совпадение вероятностной оценкой.
- Выбор алгоритма и решение о допуске/victim принадлежат policy backend. Storage не выбирает жертву самостоятельно.
- Controller владеет обработкой конкретного слова и его неизменяемым решением. Он координирует lookup/policy и превращает результат в descriptor.
- Изменения состояния policy, связанные с обработанным словом, не должны повторяться при ожидании `desc_ready`. Они применяются по commit, вместе с записью строки для `SYNC`.
- Serializer владеет активным кадром после передачи descriptor из frame buffer. Дальнейшие изменения словаря не могут изменить уже активные байты кадра.

## 4. Ответственность модулей

### `tdl_dict_storage.sv` — память и занятость строк

Storage выполняет только операции с массивом:

1. При reset очищает массив и valid-биты; `flush` сбрасывает валидность словаря.
2. При `wr_en` записывает `wr_data` в `wr_index` и устанавливает valid-бит строки.
3. Выдаёт массив и valid-биты для поиска, а также `occupied_count`, `dict_full` и первый свободный индекс.

`next_free_index` — адрес первой строки с `valid=0`, а не write-enable. При полном словаре адрес может быть нулём из-за начального значения вычисления; это не означает, что строка 0 доступна. Разрешение записи и выбор жертвы должны прийти извне. Перед записью требуется допустимый индекс и согласованная команда; storage по плану не должен автономно перезаписывать ключ при `dict_full`.

Storage принимает `wr_en` только при `wr_index < DICT_SIZE`. `flush` имеет приоритет над записью в тот же такт и очищает valid. Поиск игнорирует payload невалидных строк.

### `tdl_parallel_search.sv` — точное сравнение

Поиск строит для каждой строки условие:

```text
match[i] = valid_bits[i] && (dict_words[i] == search_word)
hit      = OR(match)
hit_key  = минимальный i, для которого match[i] = 1
```

Сравниваются все `DATA_WIDTH` битов; для базовой версии это 32 бита. Поиск не обновляет состояние и не различает алгоритмы. Если из-за начального состояния или внешней ошибки одинаковое слово находится в нескольких строках, детерминированно возвращается минимальный индекс. Штатный commit новых слов должен не создавать такие дубликаты.

Существующая реализация комбинационная. План допускает позднее зарегистрировать поиск, если цена/задержка комбинационной схемы окажется неприемлемой. Добавление pipeline не должно менять valid/ready-контракт controller/policy: ответы остаются стабильными до приёма.

### `tdl_dict_unit.sv` — составной интерфейс словаря

Unit инстанцирует ровно один storage и один parallel search. Он проводит массив и валидность от storage к search и возвращает hit/key. При записи выбирает `wr_key`, если выставлен `use_custom_index`, иначе `next_free_key`.

Unit не должен выбирать занятую жертву или применять конкретный алгоритм: это делает policy и затем выдаёт подтверждённую команду записи controller/storage. Статусы `dict_full` и `next_free_key` сообщают policy о состоянии строк, но сами по себе не являются admission-решением.

В текущем интерфейсе есть `add_en`, `use_custom_index`, `wr_key`, `wr_data`, `flush_dict`. При подключении к целевой архитектуре `add_en` следует увязать с commit `SYNC`, а автоматический адрес использовать только для допускаемой вставки в свободную строку. В целевой интеграции каждый SYNC передаёт явный ключ controller в wr_key при use_custom_index=1, включая вставку в свободную строку. Для SLRU replacement возможен и при неполном общем словаре; его нельзя заменять автоматическим next_free_key.

### `tdl_tx_policy.sv` — общий интерфейс алгоритма

Policy получает сохранённые controller слово, hit/miss и hit key, снимок конфигурации. Запрос может занять несколько тактов; controller держит запрос до `req_valid && req_ready`, затем ждёт ответ `rsp_valid && rsp_ready`. Bypass пропускает lookup и policy и формирует RAW.

При hit политика всё равно вызывается: она может обновить метаданные строки. Тип результата при этом остаётся `KEY` с exact hit key. При miss policy возвращает `admit`, ключ для записи (если он есть) и флаг BF-отсева. Controller формирует `SYNC`, если вставка разрешена, иначе `RAW`. Policy должна удерживать результат и подготовленные изменения до commit; backpressure descriptor не должен повторно увеличить счётчик, ещё раз повернуть Clock hand или повторно обновить CMS/BF.

`tdl_tx_policy` является фасадом/диспетчером, а не вторым владельцем всех метаданных. Активный backend хранит собственное состояние; при реализации лучше не размножать один и тот же счётчик или usage vector в wrapper и backend.

## 5. Обработка одного слова и порядок обновления

Целевая транзакция одного слова выглядит так:

1. **Захват FIFO.** Controller выполняет `word_take`, одновременно снимает головное слово FWFT FIFO и фиксирует применимые для него `BYPASS_EN`/настройки policy. После этого FIFO может выдать следующее слово; весь текущий расчёт использует сохранённый `word_data`.
2. **Exact lookup.** В обычном режиме controller запрашивает поиск. Lookup отвечает hit/key или miss. В Bypass этот шаг пропускается.
3. **Политика.** Controller передаёт hit/miss и снимок настроек. Backend формирует descriptor-решение и подготовленные изменения метаданных; расчёт может быть многоцикловым (например, Clock scan или чтение CMS). Aging текущего слова запускается после commit и блокирует следующий запрос.
4. **Подготовка descriptor.** При Bypass или отказе admission — RAW; при hit — KEY(hit key); при допускаемом miss — SYNC(policy key, исходное слово). Payload фиксируется до handshake.
5. **Commit.** На `desc_valid && desc_ready` descriptor переходит к следующему блоку. На том же фронте SYNC записывает пару key/data, а policy применяет подготовленные изменения ровно один раз. RAW также может commit-ить статистику TinyLFU, уже рассчитанную для этого слова. В Bypass статистические структуры заморожены.
6. **Следующее слово.** Следующий lookup запускается после фиксации предыдущего commit, чтобы видеть новую строку. Одновременная выдача предыдущего кадра по SDR и обработка следующего слова разрешена; они используют независимые регистры.

```text
AXIS FIFO       Controller         Search / Policy        Dict + frame buffer
   │                │                     │                         │
   ├─ word_take ───>│                     │                         │
   │                ├─ lookup request ───>│                         │
   │                │<─ hit/key or miss ──┤                         │
   │                ├─ policy request ───>│                         │
   │                │<─ admit/key ────────┤                         │
   │                ├─ descriptor valid ───────────────────────────>│
   │                │<──────────────────────────── ready / commit ──┤
   │                ├─ SYNC write + policy commit                   │
```

Критический порядок на проводе: если commit слова `X` записал `(K, X)` в TX-словарь, следующий hit для `X` может выдать `KEY(K)` до того, как RX физически получил SYNC. Это безопасно только потому, что frame buffer и serializer сохраняют последовательность `SYNC(K,X) → KEY(K)`. Нельзя отменять или переставлять уже принятый descriptor при выключении TX или смене конфигурации.

## 6. Алгоритмы и их владельцы

Утверждённые правила находятся в [общей спецификации](../../spec.md), §8. Exact hit для всех режимов даёт KEY исходного ключа. Descriptor и физическая запись принадлежат controller, metadata — соответствующему backend.

### 6.1. Clock (ALGO_SEL=10)

Usage-биты и clock_hand принадлежат Clock policy. Hit устанавливает usage, не двигая руку. Свободная вставка выбирает минимальный free key и тоже не двигает руку. При полном словаре second-chance обход с явным wrap по DICT_SIZE подготавливает очистки и victim; commit применяет очистки, устанавливает usage victim=1 и руку next(victim). При всех usage=1 временные очистки должны учитываться при повторном посещении.

### 6.2. Pure LFU (ALGO_SEL=11)

4-битный counter на resident-строку, reset=0, insert=1, hit saturating до 15. Miss предпочитает свободный ключ, при full выбирает valid-only минимум, равенства — минимальный ключ. Miss всегда даёт SYNC. Aging отсутствует; это ограничение насыщаемого Pure LFU, а не открытый вопрос.

### 6.3. SLRU (ALGO_SEL=01)

N_prob=SLRU_CFG_REG, N_prot=DICT_SIZE-N_prob; допустимо 1 <= N_prob < DICT_SIZE. Неверная настройка блокирует SLRU через cfg_valid. Сегменты являются логическими квотами, а не диапазонами физических ключей.

Miss занимает свободную строку только при prob_count<N_prob; иначе заменяет Probationary LRU, даже если Protected не заполнен. Hit Probationary promote-ится; при полном Protected его прежний LRU demote-ится на освобождённое место Probationary. Дополнительного eviction на hit нет, физические ключи не меняются.

Rank — уникальная позиция 0…count-1: hit двигает к MRU, сдвигая только прежние меньшие rank; удаление сжимает большие rank; вставка в MRU увеличивает rank остальных. Эти обновления не переполняются при правильных count и фиксируются одним commit.

### 6.4. TinyLFU (ALGO_SEL=00)

Exact hit увеличивает только 4-битный local counter. При miss после lookup запускается tabulation hash. BF_EN=1: проверить два адреса по active/old до вставки слова; подготовить установку обоих битов в active. Отрицательный результат даёт RAW без CMS; возможный false positive не является dictionary hit.

BF pass либо BF_EN=0 запускает CMS. c0_next/c1_next вычисляются с насыщением: CU увеличивает только counters, равные одному старому минимуму; standard увеличивает оба. f_new=min(c0_next,c1_next) выдаётся до физической записи, которая ждёт commit.

Свободный ключ используется первым после допуска BF. При full victim — valid-only минимум local counters, tie по минимальному ключу; вставка только при f_new>f_min. Local counter insert=1, без наследования victim/CMS history; hit saturating до 15. Без aging при всех local=15 дальнейший admission невозможен при 4-битном f_new.

### 6.5. Aging и Bypass

Период N считает policy_commit слов только TinyLFU, включая KEY/RAW/SYNC. После обычных обновлений N-го слова выполняется обслуживание и сброс счётчика периода. При N=0 период не накапливается. Смена N при безопасном покое начинает новый интервал с первого запроса с новым снимком.

AGING_DISABLE=1 выключает деление CMS/local counters, но BF rotation остаётся при BF_EN=1. BF_EN=0 замораживает BF, CMS на miss продолжает работать; повторное включение сохраняет BF history. Очистка old-поколения предшествует смене ролей; она может быть многоцикловой. Следующий запрос ждёт полного aging_done.

Bypass фиксируется на слове, даёт RAW без policy_commit; новые Bypass-слова metadata не меняют. Ранее принятый обычный запрос/обслуживание завершается. Runtime миграции/ручной очистки в базовой версии нет.

## 7. Транзакции и интеграция

- Порты четырёх backend и соединения с контроллером заданы в [tdl_tx_policy](../../modules/transmitter/tdl_tx_policy.md#интерфейс-с-backend-политиками). `backend_ready` доступен до запроса и объединяет готовность поиска, выбранной политики и допустимость активной конфигурации.
- Response handshake не равен commit: policy держит pending состояние до commit и конца обслуживания.
- CMS хранит адреса и будущие counters до отдельного commit от TinyLFU; BF-filtered RAW и exact hit не порождают CMS transaction.
- Valid-маска принадлежит storage и выводится через unit в policy; копии владеющего состояния не создаются.
- Свободный индекс при full недействителен. Индексы проверяются по DICT_SIZE, включая не степени двойки.
- ALGO_SEL и SLRU квоты фиксируются до первого слова и сохраняются до reset. Остальные настройки меняются в безопасном покое по §6.1.1 спецификации.
- 32-битный снимок: [1:0] ALGO_SEL, [2] CU_DISABLE, [3] AGING_DISABLE, [4] BF_EN, [7:5]=0, [15:8] N_prob, [31:16] AGING_PERIOD.
- FIFO/очередь кадров сохраняют порядок SYNC→KEY. Metadata политик существуют только на TX; RX применяет явные ключи из кадров.

## 8. Оставшиеся задачи реализации

Алгоритмические решения выше утверждены. Unit выдаёт `valid_bits` и зарегистрированный ответ lookup. Для сквозного тракта остаются подключение словаря и policy к controller в top и проверка busy/done. Выбор аппаратного отображения памяти и проверка задержек CMS/Clock scan относятся к синтезу и проверке тайминга.

Предыдущая оценка TinyLFU около 2,4 КиБ учитывала изменяемое состояние без ROM. 16 byte-ROM tabulation hash требуют ещё 40960 бит = 5 КиБ. Полный расчёт полезного состояния — §8.8 спецификации; FPGA-ресурсы/тайминг требуют синтеза. Симуляция и синтез этим документом не заменяются.

## 9. Соответствие текущему RTL

| Файл | Что реализовано сейчас | Следующий необходимый шаг по плану |
| --- | --- | --- |
| `rtl/transmitter/tdl_dict_storage.sv` | Массив, valid, запись с проверкой индекса, flush, число занятых и первый свободный индекс | Подключить команду записи от commit SYNC через unit |
| `rtl/transmitter/tdl_parallel_search.sv` | Комбинационный точный поиск по валидным строкам, минимальный ключ при дубликатах | Проверить ресурс/тайминг; при необходимости зарегистрировать без смены протокола ответа |
| `rtl/transmitter/tdl_dict_unit.sv` | Соединяет storage и search, блокирует автовставку при full, выводит valid-маску и удерживает ответ lookup | Подключить к controller и policy в top |
| `rtl/transmitter/tdl_tx_pkg.sv` | Enum `FRAME_RAW`, `FRAME_KEY`, `FRAME_SYNC` | Добавить коды алгоритмов и формат policy_cfg по §8.10 общей спецификации |
| `rtl/transmitter/gf2_xor_hash.sv` | Комбинационный XOR hash с параметрами ширины и seed | Сохранить как отдельный модуль; для TinyLFU реализовать tdl_tab_hash по §8.1 общей спецификации |
| `rtl/transmitter/tdl_tx_controller.sv` | FSM захвата, lookup/policy handshake, descriptor, commit и SYNC write outputs | Интегрировать с top, словарём, policy и frame buffer; проверить совместимость интерфейсов |
| `rtl/transmitter/tdl_tx_top.sv` | Текущая связка top использует ранние `dict_hit/dict_key/force_sync`; нового словаря в top нет | Пересобрать интеграцию вокруг lookup/policy/commit интерфейса по baseline plan |

Для порядка реализации план предлагает сначала проверить storage/search/unit, затем подключить Clock как первую policy; после неё — Pure LFU и SLRU, затем TinyLFU (hash, BF, CMS, aging). Такая последовательность отделяет правильность exact deduplication от качества admission и replacement.
