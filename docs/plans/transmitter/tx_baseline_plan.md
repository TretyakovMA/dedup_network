# План базовой реализации передатчика TDL

Это план будущих изменений, а не описание уже реализованного устройства. Корневой README не использовался. При подготовке плана RTL и тестбенчи не изменялись, моделирование не запускалось.

## 1. Границы реализации

Цель — получить проверенный тракт `PHY → AXI-Stream → FIFO → дедупликация → SDR`, управляемый через существующий SPI, с перекрытием обработки следующего слова и передачи текущего кадра.

Внешние порты `tdl_tx_top` остаются прежними. Источник данных — PHY через `s_axis_tdata/tvalid/tready`. Существующий `s_axis_tlast` сохраняется; на этом этапе границы AXIS-пакетов не влияют на кодирование: одно принятое 32-битное слово образует один RAW, KEY или SYNC. `tlast` пока не буферизуется и не передаётся по SDR; это явное ограничение версии.

Входят в план:

- RAW, KEY и SYNC, точное сравнение всех 32 бит;
- входное FIFO, словарь, раннее извлечение слова и упорядоченная передача;
- `TX_EN`, `BYPASS_EN`, делитель SDR и обработка `sdr_ready`;
- алгоритмы `ALGO_SEL`, их статистика, автоматическое aging и ротация BF;
- подключение статусов, счётчиков и предусмотренных для реализованных функций прерываний.

Не входят: CRC во всех режимах, I²C, `CMD_REG`, `SOFT_RESET`, отдельный обработчик аппаратного сброса/восстановления и командная очистка словаря. Ручные `BF_RESET` и `FORCE_ROTATE` также исключены из базовой версии; автоматическая ротация остаётся частью TinyLFU. Наличие этих полей в сгенерированных регистрах не означает поддержку действий в этой версии.

**Существующий вход `rst_n` сохраняется для начальной инициализации.** Под исключением аппаратных сбросов здесь понимается отсутствие новых управляющих механизмов, а не запуск FSM, valid-битов и счётчиков из неопределённого состояния. Сброс посреди передачи не обеспечивает согласование с RX: восстановление после него вне этого этапа.

Под «базовой функциональностью» здесь понимается весь тракт без перечисленных исключений, включая четыре алгоритма спецификации. Для первой работающей сборки предлагается реализовать Bypass и Clock, затем добавить остальные режимы. Промежуточную сборку с одним алгоритмом нельзя считать поддерживающей все значения `ALGO_SEL`.

## 2. От чего отталкиваемся

| Существующий блок | Что есть сейчас | Что нужно сделать |
| --- | --- | --- |
| `fifo`, `axis_input_fifo` | FWFT: головное слово видно до чтения; указатель продвигается по `posedge clk`. Запись блокируется при full | Сохранить интерфейс; проверить интеграцию раннего чтения, одновременные операции и ограничения DEPTH |
| `spi_tx_regs_wrapper` + `tx_regs` | SPI-доступ и сгенерированный регистровый блок; bit-bash ранее проходил | Сохранить имя. Проверить подключения конфигурации/статуса, IRQ, чтение живых счётчиков и переход SPI ↔ clk |
| `tdl_tx_top` | Соединяет FIFO, SPI и контроллер | Сейчас словарь не подключён, `dict_hit/dict_key/force_sync` не имеют источника; `hwif_in` не заполнен, настройки из `hwif_out` не управляют трактом |
| `tdl_tx_controller` | Захват слова, lookup/policy valid-ready, descriptor и commit | Подключить к обновлённому top, адаптеру поиска, policy и frame buffer |
| `tdl_dict_storage`, `tdl_parallel_search`, `tdl_dict_unit` | Хранение, valid-биты, поиск совпадения и свободного ключа | Сначала проверить отдельно. Добавить безопасное обновление, интерфейс метаданных и защиту недопустимого индекса |
| `gf2_xor_hash` | Комбинационная линейная XOR-функция с масками | Не считать реализацией tabulation hashing из §8.1. Для соответствия спецификации нужен другой хэш-блок |

Успешные модульные тесты не доказывают готовность к синтезу и аппаратную корректность переходов между тактовыми доменами. В частности, SPI-обёртка содержит обработку событий `spi_sclk/spi_cs_n` с использованием ответов регистра на `clk`; перед аппаратной реализацией нужен отдельный разбор этого интерфейса.

Сериализация выделена в tdl_tx_serializer. Порядок SYNC на проводе следует §4.1 общей спецификации — **header/key/data**.

Обновлённый пользователем timeout в `axis_input_fifo` сохраняется. Старый результат теста до исправления таймаута не заменяет повторную проверку на этапе реализации.

## 3. Предлагаемая архитектура

```text
PHY AXIS
   │
axis_input_fifo
   │ FWFT + pop
tdl_tx_controller ──────────→ tdl_dict_unit
   │ регистр слова             ├─ tdl_parallel_search
   │                           └─ tdl_dict_storage
   ├────────────────────────→ tdl_tx_policy
   │                           ├─ Clock / LFU / SLRU
   │                           └─ TinyLFU: hash + BF + CMS
   │ descriptor {type, key, data}, valid/ready
   ▼
tdl_tx_frame_buffer          ← один ожидающий кадр
   │ descriptor, valid/ready
   ▼
tdl_tx_serializer            ← отдельный активный кадр
   │                 ▲
   │            tdl_sdr_timing
   ▼                 │
sdr_data / sdr_clk / sdr_ready

SPI → spi_tx_regs_wrapper → tx_regs → tdl_tx_reg_bridge
                                           │ конфигурация
                                           ▼
                             controller / policy / timing
                                           ▲
                         tdl_tx_stats ──────┘ статусы, события
```

Вся новая управляющая логика работает от `clk`. `sdr_clk` — зарегистрированный выходной сигнал для RX, а не внутренний clock для FIFO и FSM. Сигналы разрешения фаз SDR формируются в домене `clk`.

Разделение на блоки служит независимой проверке. На первом этапе регистр слова можно оставить внутри контроллера, буфер дескриптора — реализовать одним набором регистров. Отдельные модули для каждого мультиплексора, счётчика битов или регистрового поля не нужны.

Сначала можно использовать комбинационный поиск/выбор минимума, но их задержку и ресурсную стоимость проверять синтезом. Каналы valid/ready допускают многоцикловый расчёт ответа Clock и CMS. Обслуживание статистики текущего слова начинается после commit и блокирует следующий запрос. Сигналы между контроллером, фасадом и политиками заданы в [tdl_tx_policy](../../modules/transmitter/tdl_tx_policy.md#интерфейс-с-backend-политиками).

Hash в базовой интеграции запускается после exact miss через policy. Параллельный запуск с lookup требует нового раннего интерфейса и отложен. BF/CMS работают только TinyLFU и не обновляются на exact hit; hit увеличивает local resident counter. Bypass не запускает новых обновлений, ранее принятые работа/обслуживание завершаются.

При отрицательной BF-проверке TinyLFU выдаёт RAW даже при свободном месте. False positive может пропустить первое появление; нельзя обещать RAW для каждого первого слова. После BF pass или при BF_EN=0 свободная строка используется первой; при полном словаре требуется строгое f_new>f_min.

Обслуживание BF/CMS может быть многоцикловым, следующее слово ожидает aging_done. Память выбирается при RTL; обязательной очистки BF за один такт нет. Для SLRU действует исключение из глобального free-first: при заполненной Probationary квоте её LRU заменяется даже при свободной ёмкости Protected.

Подробные утверждённые правила и внутренняя упаковка policy_cfg находятся в [spec.md](../../spec.md), §8; новые и существующие модульные страницы ссылаются на этот контракт.

`CNT_TOTAL_WORDS` увеличивается на приёме AXIS (`tvalid && tready`); `CNT_RAW/KEY/SYNC_FRAMES` — после завершения соответствующего кадра; `CNT_BF_FILTERED` — один раз при подтверждённом решении BF отвергнуть слово. Эти моменты различаются: при занятом тракте количество принятых слов больше числа переданных кадров, и это нормально.

Событие полного FIFO соответствует смыслу спецификации: достижение full, а не любое `tvalid && !tready` — последнее является нормальным удержанием данных по AXIS. Для `HIGH_HIT_RATE` сравнивать расширенные произведения `255 * CNT_KEY_FRAMES > THRESH * CNT_TOTAL_WORDS`, исключив нулевой знаменатель; определить поведение при переполнении счётчиков. Для базовой версии принято насыщение всех пяти 32-битных счётчиков на 0xFFFFFFFF, как описано в §6.1.3 общей спецификации и документации tdl_tx_stats.

Накопительные IRQ-флаги сохраняются до W1C. При одновременном W1C и аппаратном событии `tx_regs` отдаёт приоритет `hwset`. Wrapper формирует `spi_irq` с учётом `INT_ENABLE_REG`.

Для `SPI_ADDR_ERR` нужен импульс реальной ошибочной транзакции от SPI/регистрового интерфейса. Для несуществующих I²C-событий подать нули. `FLUSH_BUSY`, `RESET_BUSY` — нули в этой версии после начальной инициализации. `FSM_STATE` получить от controller; не трактовать `FIFO_EMPTY` как отсутствие активного/ожидающего кадра.

PeakRDL генерирует буферизованное чтение пяти 32-битных счётчиков по настройке `buffer_reads`. Прямой стенд CPUIF проверяет целостность снимка при изменении счётчика между чтениями байтов.

## 5. Раннее чтение FIFO и момент обновления словаря

### 5.1. Владение словом

Контроллер получает собственный регистр `word_data` с признаком занятости. Когда есть место, разрешена обработка и FIFO не пусто:

```text
word_take = tx_enabled && word_slot_ready && !fifo_empty
fifo_rd_en = word_take
на posedge clk при word_take: word_data ← fifo_rdata
```

У текущего FWFT FIFO на этом же фронте продвигается указатель чтения. В регистр захватывается прежнее головное слово; следующий элемент становится виден после фронта. Дальнейшие сравнения, хэши и descriptor относятся только к `word_data`, а не к меняющемуся `fifo_rdata`.

`fifo_rd_en` формируется в домене `clk` и означает передачу владения словом контроллеру. Его не нужно переносить просто с последнего бита на первый: правильная точка — захват во внутренний регистр, который может произойти ещё до начала передачи соответствующего кадра.

### 5.2. Два независимых процесса

1. Serializer передаёт кадр A из собственных регистров.
2. Controller извлекает и обрабатывает B, пока идёт передача A.
3. Готовый descriptor B помещается в frame buffer.
4. Пока буфер занят, следующий результат нельзя потерять или перезаписать; controller удерживает состояние, а входное FIFO обеспечивает обратное давление до PHY.
5. После A serializer забирает B; frame buffer освобождается для следующего результата.

Таким образом, есть регистр обрабатываемого слова, один ожидающий descriptor и один активный кадр. Глубокая очередь кадров пока не требуется. Перекрытие обработки и передачи не гарантирует отсутствие пауз при любой задержке алгоритма, но устраняет искусственное ожидание конца SDR для каждого чтения FIFO.

### 5.3. Подтверждение изменений (commit)

Утверждённый контракт: `commit = desc_valid && desc_ready`. На одном подтверждении descriptor гарантированно сохраняется в очереди, а словарь и метаданные обновляются ровно один раз. Пока очередь заблокирована, повторять запись, увеличение частоты или BF/CMS update нельзя. Политика рассчитывает решение один раз и удерживает его; изменения состояния применяются по подтверждению. Для многоциклового Clock нужно сохранить результат обхода/набор очищаемых usage-битов до commit.

Следующий запрос к словарю допускается после фиксации предыдущего commit, чтобы он видел записанное значение. Для первого варианта достаточно не запускать новый поиск в тот же фронт записи; forwarding и несколько незавершённых поисков не требуются.

Пример: B вызывает SYNC для `K → X`. После commit C с тем же X может получить KEY(K), хотя B ещё не дошёл до RX. Это корректно только при строгом порядке передачи `... SYNC(K,X), KEY(K)`. Уже принятые descriptors нельзя отменять или переставлять при выключении TX/смене режима. Serializer никогда не перечитывает payload активного кадра из живого словаря.

## 6. SDR и настройки во время работы

`tdl_sdr_timing` реализует формулу спецификации:

```text
F_SDR = F_SYS / (2 * (D + 1)), D = SDR_CLK_DIV[15:0]
```

Каждый полупериод длится `D+1` тактов `clk`, включая `D=0` и `D=65535`; разрядности счётчиков/выражений должны покрывать 65536 тактов. При 50 МГц максимальная частота SDR — 25 МГц. Существующее пропускание `clk` через latch/gate не соответствует этой формуле.

- Бит выставляется заранее в низкой фазе. Учёт принятого бита выполняется только при фактическом разрешённом положительном фронте SDR.
- При `sdr_ready=0` новый положительный фронт не формируется, непереданный бит и индексы удерживаются. Уже начатая высокая фаза завершается штатным спадом; её нельзя обрезать асинхронным AND с ready.
- После последнего бита завершить высокую фазу и вернуть `sdr_clk=0`, затем однократно выдать `frame_done` и освободить активный descriptor.
- Внешний ready должен иметь определённый временной контракт относительно `clk`/принимающего фронта. Для базовой модели считать его синхронным `clk`; если реальный RX асинхронен, отдельно спроектировать синхронизацию и допустимые биты «в пути». Простые два триггера без такого контракта не обеспечивают мгновенную остановку линии.
- Фиксировать D при начале кадра; изменение регистра в процессе кадра не меняет его полупериоды. Два байта D не образуют атомарную запись: в базовом программном протоколе обновлять оба при остановленном TX.

Предлагаемая семантика `TX_EN=0`: немедленно запретить новые захваты слов/начало положительных фронтов SDR, закончить уже начатую высокую фазу, сохранить активный кадр, очередь и словарь. После включения продолжить с того же непереданного бита. Это остановка, а не отмена кадра и не сброс. Приём AXIS оставить разрешённым до full; PHY обязан соблюдать tready.

BYPASS_EN и policy_cfg фиксируются при захвате слова. ALGO_SEL и SLRU N_prob задаются до первого слова после reset и фиксируются до reset; runtime миграции нет. RX получает явные ключи и не повторяет TX replacement policy.

Для изменения BF_EN/CU_DISABLE/AGING_DISABLE/N ПО останавливает источник, при `TX_EN=1` опрашивает пустой FIFO и idle controller в одном `STATUS_REG` и ждёт 518 периодов `clk` от завершения успешного чтения. Затем снимает `TX_EN`, записывает все значения, включает TX и возобновляет источник. Принятые кадры сохраняются. Новый период N начинается с первого слова нового снимка. Процедура описана в §6.1.1 общей спецификации.

## 7. Утверждённые решения для политик

Эти решения согласованы с §8 общей спецификации и обязательны для новых backend-ов:

| Тема | Контракт |
| --- | --- |
| BF/CMS | Только TinyLFU; hit обновляет только local counter |
| Свободные строки | Clock/LFU — первая свободная; TinyLFU — после BF pass или BF_EN=0; SLRU соблюдает квоту Probationary |
| LFU | Local insert=1, hit насыщается на 15, valid-only минимум, равенства по минимальному ключу; aging отсутствует |
| TinyLFU | Local insert=1 без переноса CMS history; f_new после CU/standard update; строгое > при полном словаре |
| Aging | Только TinyLFU; счёт по policy_commit KEY/RAW/SYNC; обслуживание после N-го commit; N=0 отключает период |
| Флаги | AGING_DISABLE отключает деление, но не BF rotation; BF_EN=0 замораживает оба поколения, включая ротацию |
| SLRU | N_prob — число строк, 1 <= N_prob < DICT_SIZE; точные ranks, фиксированные квоты, metadata transitions без смены ключей |
| Конфигурация | Неверный SLRU размер блокируется cfg_valid через backend_ready, без clamp; снимок 32 бит по §8.10 |
| Hash | Tabulation с фиксированными ROM; эластичный однорегистровый канал; запуск после miss |
| CMS commit | Response содержит предсказанный post-update минимум; память записывается по отдельному commit |
| Валидность | Владелец — storage, valid_bits передаются через unit, не дублируются в policy |
| Reset/команды | Runtime migration/flush, BF_RESET/FORCE_ROTATE и SOFT_RESET исключены из базового этапа |

Данные строго 32 бита, DICT_SIZE=2…256, включая не степени двойки; индекс проверяется по реальному размеру. FIFO первоначально поддерживает глубины 8/16/32/64. CONFIG_PENDING в базовом тракте остаётся 0; новый протокол применения настроек или новый CSR этим документом не добавляется.

Аппаратное отображение памяти и задержки CMS/Clock требуют проверки синтезом. При изменении длительности обслуживания TinyLFU проверяется граница ожидания из §6.1.1.

## 8. Порядок реализации и проверки

| Этап | Работа | Условие завершения |
| --- | --- | --- |
| 1. Зафиксировать контракты | Формат descriptor, точки word_take/commit/frame_done, поведение enable/ready, ограничения параметров | Есть согласованные временные диаграммы и эталонные правила; исключённые функции явно отключены |
| 2. Тракт RAW | Новый controller, frame buffer, serializer, timing; RAW без обращения к словарю | Поток PHY восстанавливается без потерь/дубликатов при случайном ready; правильные D=0/1/максимум; следующее слово извлекается до завершения предыдущего кадра |
| 3. Словарь | Отдельно проверить storage/search/unit; затем подключить Clock как первый полноценный алгоритм | Первый miss даёт SYNC, повтор — KEY; свободные ключи, полный словарь, замещение и последовательность SYNC→KEY корректны |
| 4. Регистры | TX_EN/BYPASS/D, статусы, счётчики, W1C/IRQ, shadow-read | SPI-настройки реально меняют поведение; данные и кадры не теряются при паузах; многобайтные чтения согласованы |
| 5. LFU и SLRU | Два автономных policy-блока через общий интерфейс | Насыщение частот, равенства, границы сегментов, promote/demote и длительные потоки совпадают с моделью |
| 6. TinyLFU | Таблицы хэша, BF, CMS, admission и aging | Коллизии не дают ложного dictionary hit; BF-отсев, CU_DISABLE/BF_EN, ротация и aging совпадают с моделью |
| 7. Интеграция базовой версии | Все поддержанные режимы, ограничения и диагностика | Восстановленные из SDR слова совпадают с принятыми AXIS; повторные прогонки с разными seed; синтез подтверждает допустимость структуры и времени |

Минимальное управление `TX_EN` и делителем подключается уже на этапе 2; этап 4 завершает всю наблюдаемость и SPI-семантику, а не откладывает конфигурацию тракта до конца.

В интеграционном scoreboard нужен небольшой программный декодер RAW/KEY/SYNC с собственным RX-словарём. Это эталон для тестбенча, не начало реализации RTL-приёмника. Принимаемые AXIS-слова помещаются в очередь ожидания; декодированные слова сравниваются по порядку. Такой тест проверяет ранний pop, commit и замещение лучше, чем одно наблюдение `fifo_rd_en`.

Обязательные сценарии: длительный stall SDR; FIFO full при соблюдении AXIS; один и тот же элемент сразу после SYNC; замена ключа, пока предыдущий кадр ещё передаётся; заполненный frame buffer; TX_EN в обеих фазах SDR; изменение D внутри кадра; пауза между байтовыми SPI-записями; завершение высокой фазы последнего бита; подтверждение ровно одного pop/commit/frame_done на слово. Таймаут и финальный PASS/FAIL остаются ответственностью каждого тестбенча.

## 9. Размещение файлов

Новые TX-блоки и `tdl_tx_pkg.sv` первоначально размещать в `rtl/transmitter/`; текущие FIFO остаются в `rtl/common/`. `tdl_sdr_timing` и hash переносить в common только при появлении реального переиспользования. Сгенерированные файлы остаются в `rtl/gen/`, исходник карты — `rdl/tx_regs.rdl`.

Стенды новых блоков: `dbg/tb/transmitter/<имя модуля>/{run,testbench}`. Общие модели/агенты выносить в `dbg/common` по фактической необходимости. Интеграционный стенд — `dbg/tb/transmitter/tdl_tx_top`. Перед его запуском проверить существующие пути: его Makefile и списки интерфейсов ранее не входили в доработку трёх рабочих стендов.

Краткие описания реализованных модулей: `docs/modules/transmitter/<имя модуля>.md` — назначение, параметры, порты, правила valid/ready, задержки и ссылка на стенд. Этот файл остаётся архитектурным планом; по мере реализации в нём можно отмечать завершённые этапы и принятые решения.

## 10. Покрытие документацией

Все 26 модулей и пакетов из таблиц §4.1–4.3 имеют модульное описание по ссылке в имени файла. tx_regs и tx_regs_pkg описаны совместно. FIFO находятся в rtl/common, их страницы размещены в docs/modules/common.

Контракт SPI и результаты проверки CSR описаны в модульных страницах. Для интеграции остаются сборка top, подключение событий к CSR, сквозная проверка программной последовательности смены настроек и проверка аппаратных задержек SPI.
